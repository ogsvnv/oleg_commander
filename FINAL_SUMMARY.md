# Oleg Commander - Завершённый Проект

## Описание

Oleg Commander — это собственный аналог Desktop Commander для удалённого управления компьютерами через Model Context Protocol (MCP). Проект предоставляет AI-ассистентам безопасный доступ к локальной файловой системе, терминалу Linux, SSH-серверам, Git-репозиториям и другим системным ресурсам.

## Реализованные возможности

### 1. Архитектура
- Четкая модульная структура проекта
- MCP сервер на основе официального SDK
- Конфигурация через YAML и переменные окружения  
- Централизованное управление безопасностью
- Аудит действий с журналами

### 2. Поддерживаемые инструменты
- **Файловая система**: 
  - Просмотр каталогов и файлов
  - Чтение/запись текстовых файлов
  - Поиск по имени и содержимому
  - Управление файлами (копирование, перемещение, удаление)
  - Получение информации о файлах

- **Терминал**: 
  - Выполнение команд в shell
  - Поддержка тайм-аутов и ограничений размера вывода

- **SSH**: 
  - Работа с указанными серверами
  - Проверка подлинности хостов
  - Передача файлов через SFTP
  - Выполнение команд на удалённых серверах

- **Git**: 
  - Статус репозитория
  - Изменения и история коммитов
  - Управление ветками
  - Коммиты и выгрузка изменений

- **Системные процессы**: 
  - Перечень активных процессов
  - Информация о процессах
  - Управление процессами (удаление)

- **Systemd сервисы**:
  - Статус и логи сервисов
  - Перезапуск сервисов

- **Docker (опционально)**:
  - Список контейнеров
  - Логи и управление контейнерами

### 3. Безопасность
- Контроль доступа к каталогам
- Проверка подлинности SSH-хостов  
- Запрет path traversal атак
- Требование подтверждения опасных операций
- Ограничение времени выполнения команд
- Журналирование всех действий

### 4. CLI интерфейс
- `oleg-commander start` - запуск сервера
- `oleg-commander doctor` - диагностика
- `oleg-commander status` - статус
- `oleg-commander logs` - просмотр журналов  
- `oleg-commander approvals` - запросы на одобрение
- `oleg-commander approve/reject` - управление заявками

### 5. MCP Транспорт
- Поддержка stdio для локального использования
- Поддержка Streamable HTTP endpoint `/mcp`
- Проверка подлинности (через стандартные механизмы MCP)

## Запуск проекта

```bash
# Установка (в режиме разработки)
pip install -e .

# Запуск локально через stdin
oleg-commander start

# Запуск через HTTP (по умолчанию 127.0.0.1:8765)  
oleg-commander start --transport http
```

## Системные требования

- Python 3.11+
- Операционная система: Ubuntu Linux  
- Пользователь: ogsvnv
- Установленные библиотеки:
  - mcp >= 2.0.0
  - asyncssh >= 2.14.0
  - httpx >= 0.25.0
  - pydantic >= 2.5.0
  - pytest >= 7.0.0

## Известные ограничения

- В режиме read-only некоторые операции (запись, удаление) недоступны
- SSH-подключения требуют явного указания разрешённых серверов
- Docker интеграция опциональна и не включена по умолчанию
- Некоторые функции имеют заглушку для демонстрации схемы
- Безопасность ограничена возможностями текущих SDK

## Установка через systemd

Сервис автоматически запускается от пользователя ogsvnv с автоматическим перезапуском при ошибках.

```bash
sudo cp deployment/oleg-commander.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable oleg-commander.service
sudo systemctl start oleg-commander.service
```
